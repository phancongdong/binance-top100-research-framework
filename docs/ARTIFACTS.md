# Output contract and verification

The output directory begins empty. `state.json` records schema, demo label, spec/code/data identity hashes, the completed phase prefix, each artifact path and SHA-256, an in-flight phase marker, and a checksum over canonical JSON. `phases/<PHASE>.json` contains its phase, the identity, adapter evidence and label. Phase files are created exclusively and never overwritten. Every resume and verify checks the state checksum, phase sequence, manifest paths, file bytes, phase identity and unexpected phase files. Paths must be relative to the output root and cannot traverse a parent or a symlink.

Before each callback, the in-flight marker is persisted. A crash or rejected callback leaves it unresolved and blocks resume; the operator must inspect custody and choose a separate recovery procedure. A successful callback must return `accepted: true` and JSON evidence, after which its protected file is recorded in state. This is a trusted, single-process local example, not an atomic distributed transaction. Concurrent writers, malicious rewriting of both evidence and checksums, file replacement between path checks and I/O, and proof of a truly untouched holdout are outside its security boundary. Preserve output directories independently if stronger custody is needed.

`demo` recomputes the package code hash and synthetic source/spec identity, so changing them causes resume to fail. `verify` checks the stored local artifact integrity but cannot establish whether the original source timestamps or phase claims were truthful. A file hash is an integrity binding, not admission, investment performance, or live authority.
